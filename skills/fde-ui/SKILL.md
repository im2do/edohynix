# 필요한 판단과 다음 행동이 보이는 화면

응답과 새로 작성하는 사용자 화면 문구는 기본 한국어로 쓴다. 원문 인용·고유명사·코드 식별자는 보존한다. 뜻이 같은 한자나 일본어 단어를 한국어 설명에 섞지 않는다. 사용자가 다른 언어를 요청하면 그 요청을 따른다.

FDE_HARNESS.json이 있으면 실제 package·progress·state 경로를 확인한다. 없으면 현재 키트의 scripts와 과제 폴더의 기존 기록을 사용한다. 기록이 없을 때의 생성·미저장 처리는 fde-track을 따른다. 없는 WORKSTATE를 읽었다고 가정하거나 기존 기록을 초기화하지 않는다.
## 입력
주 사용자, 가장 중요한 작업, 실제 데이터 열, 상태·오류와 권한. 디자인 참고는 선택 사항이다.

## 절차
1. 처음 보는 사람이 ‘무엇을 확인하고 무엇을 누르는가’를 설명하는 한 문장을 정한다.
2. 핵심 입력·목록·결과를 우선 배치한다. 상세 근거는 펼쳐보기로 제공하고 원문 위치로 연결한다. 모든 내용을 카드로 쪼개지 않는다.
3. 데이터 많음/없음/로딩/실패/미확인/처리 완료 상태를 구분한다. 숫자의 단위와 기간을 표시한다. 정상과 정보 부족을 같은 초록색 성공 배지로 표시하지 않는다.
4. 필터·검색·정렬을 붙였다면 전체 건수와 표시 건수, 필터 초기화를 제공한다. 숫자 정렬과 문자열 정렬, ID 앞자리 0 보존을 확인한다.
5. 버튼에 업무 행동을 적고 처리 결과를 표시한다. 폼에는 label, 키보드 포커스, 읽기 쉬운 오류를 제공한다. 색만으로 의미를 전달하지 않는다.
6. 작은 화면에서도 필수 버튼과 표 헤더가 가려지지 않게 한다. 긴 근거는 접을 수 있게 하되 결격 이유·미확인은 숨기지 않는다.
7. 사용자에게 실제 클릭할 흐름과 기대 결과를 준다. 현재 환경에서 금지한 자동 스크린샷·브라우저 조작 도구를 실행하지 않는다.

## 표현 점검
- 같은 상태·행동에는 같은 용어를 사용한다. 제목 → 핵심 결과 → 근거 → 다음 행동 순으로 읽히게 한다.
- 숫자 열은 정렬하고 단위·대상 기간을 붙인다. 색·아이콘만으로 정상과 오류를 구분하지 않는다.
- 기본 시스템 글꼴과 명확한 대비를 우선한다. 외부 폰트·디자인 라이브러리를 자동 설치하지 않는다.
- 한 화면에 필요한 결정 정보를 우선 배치하고, 부가 설명은 접어 둔다. 실제 길이의 값·긴 오류·빈 목록으로 확인한다.

## 넘길 결과
화면별 목적 / 가장 중요한 행동 / 상태별 표시 / 사람이 확인할 3~5개 동작.
한 기능의 실제 동작 확인 후 다음 화면을 추가한다.
