# 맞았다는 주장에 확인 가능한 근거 붙이기

응답과 새로 작성하는 사용자 화면 문구는 기본 한국어로 쓴다. 원문 인용·고유명사·코드 식별자는 보존한다. 뜻이 같은 한자나 일본어 단어를 한국어 설명에 섞지 않는다. 사용자가 다른 언어를 요청하면 그 요청을 따른다.

FDE_HARNESS.json이 있으면 실제 package·progress·state 경로를 확인한다. 없으면 현재 키트의 scripts와 과제 폴더의 기존 기록을 사용한다. 기록이 없을 때의 생성·미저장 처리는 fde-track을 따른다. 없는 WORKSTATE를 읽었다고 가정하거나 기존 기록을 초기화하지 않는다.
## 입력
요구사항과 원문 근거, 구현 또는 분석 결과, 기대 결과, 실행 가능한 환경. 비공개 정답이나 이전 정답을 가정하지 않는다.

## 절차
1. 데이터 커버리지, 규칙 적용, 실제 동작을 따로 검사한다. 테스트가 모두 통과해도 입력 누락·잘못된 기준까지 증명되지는 않는다.
2. 중요한 요구마다 원문에서 기대값을 먼저 만든다. 정상 / 명확한 거절 / 등호 경계 / 필수값 누락 / 중복 / 예외 / 비해당 중 관련 사례를 고른다.
3. 계산은 원문 숫자·단위에서 작은 별도 계산으로 대조한다. 전체 합계만 맞는지 보지 말고 대상별 값과 분모·기간도 확인한다. 매핑은 순서와 방향을 검사한다.
4. 집계·변환 결과의 ID를 전체 원본 ID와 대조한다. 누락된 정상 항목도 오류다. 양성 후보만 재검사하지 말고 경계·예외 때문에 제외된 사례도 확인한다.
5. 기능은 입력→처리→저장→재열람까지 실행한다. 권한 없는 작업, 반복 클릭, 충돌 데이터, 잘못된 형식, 빈 결과, 요구된 재시작 지속성을 점검한다.
6. 실패하면 다음 네 항목만 기록한다: 입력·재현 / 기대·근거 / 실제 / 처음 어긋난 단계. 추출 오류→data, 해석 충돌→rules 또는 define, 코드 오류→build로 보낸다.
7. 같은 증상에 두 번 실패하면 다시 변경하기 전에 중간값과 최소 재현으로 가설을 나눈다. 하나의 가설씩 검사한다. 원인 미확인 상태를 해결 완료라고 하지 않는다.
8. 최신 실행의 명령·출력 파일·실패 수를 확인하고, 통과 범위와 미실행 범위를 구분한다. 스크린샷이나 AI의 완료 문장은 테스트 대체가 아니다.

## 넘길 결과
progress에 실제 검사한 요구 버전·기대값 출처·로그 파일을 연결한다. fde-track의 현 버전 상태를 재조회하고, 구현됐지만 아직 검증되지 않은 요구와 새로 들어온 요구를 누락 없이 표시한다. 테스트 수보다 필수 요구의 검증 커버리지를 먼저 확인한다.
요구ID | 원문 근거 | 입력 | 기대 | 실제 | 통과/실패/미실행 | 확인 방법·위치
최상단에는 막는 오류, 미확인 정책, 데이터 누락만 요약한다. 사람에게 모든 로그를 읽히지 않는다.
Computer Use가 금지된 환경에서는 자동 브라우저를 사용하지 않는다. 사용자에게 직접 확인할 화면 동작 3~5개와 기대 결과를 준다.


## 상태 변경 뒤에 이어지는 전체 흐름
상태를 바꾸는 기능은 한 흐름을 연속 실행한다: 변경 전 → 조작 → 변경 후 상태 → 파생 목록/후보 재계산 → 다음 버튼과 안내 → 저장·재열람. 상태 배지만 바뀌고 후보가 초기 목록에 고정되거나, 처리 완료 뒤 예전 안내가 남는지 확인한다. 이력이 보이는 것과 현재 행동 안내는 구분한다.
해당 요구에 verification_mode=transition을 지정하고 check.transition에 각 기대값·실제값·출처를 남긴다. 저장 기능이 요구되지 않은 읽기 전용 화면은 reopened에 비해당 이유를 쓴다. 단계 생략과 비해당을 혼동하지 않는다. 형식은 [transition-format.md](references/transition-format.md). 스크립트는 기록의 불일치를 찾으며 브라우저를 대신 실행하지 않는다.
