# 다른 사람이 실행하고 확인할 수 있게 마무리

응답과 새로 작성하는 사용자 화면 문구는 기본 한국어로 쓴다. 원문 인용·고유명사·코드 식별자는 보존한다. 뜻이 같은 한자나 일본어 단어를 한국어 설명에 섞지 않는다. 사용자가 다른 언어를 요청하면 그 요청을 따른다.

FDE_HARNESS.json이 있으면 실제 package·progress·state 경로를 확인한다. 없으면 현재 키트의 scripts와 과제 폴더의 기존 기록을 사용한다. 기록이 없을 때의 생성·미저장 처리는 fde-track을 따른다. 없는 WORKSTATE를 읽었다고 가정하거나 기존 기록을 초기화하지 않는다.
## 입력
요구사항, 최종 산출물, 최신 테스트, WORKSTATE의 미정 사항.

## 절차
1. 필수 요구마다 실제 구현/결과와 검증 위치를 연결한다. 미구현·미확인·검증불가를 구분하고 사용자의 결정을 바꿀 제한을 맨 위에 적는다.
2. 웹앱은 실행 명령·포트·진입 경로와 직접 볼 대표 흐름을, 분석은 입력 파일·규칙 버전·재실행 명령·결과 파일을 제시한다.
3. 결과 표나 문서는 단위·기간·모수·근거 위치와 미확인을 포함한다. 외부에 제출하는 파일에 내부 더미나 불필요한 개인정보를 섞지 않는다.
4. 최종 변경 후 필요한 테스트가 다시 실행되었는지 확인한다. 생성했다/검사했다/실제 환경에서 동작했다를 구분한다.
5. 개발·유지보수에 필요한 문제, 확인된 조건, 설계 이유, 수정, 검증과 한계를 실제 근거로 정리한다. 작업 기록을 허위로 소급 작성하지 않는다.
6. 제공 플랫폼의 제출 방법을 확인한다. 승인되지 않은 외부 저장소나 서비스로 프로젝트 자료를 전송하지 않는다.

## 최종 출력
- 결과: 실제 해결한 사용자 작업과 파일·실행 위치
- 근거: 핵심 검증 결과와 추적 가능한 위치
- 제한: 미정·미구현·미실행
- 확인 순서: 사람이 1분 안에 볼 대표 흐름

## 완료 조건
제출은 플랫폼의 실제 계약을 읽고 확인한다. 파일 요구가 있으면 progress의 artifacts에 경로·형식·근거를 등록하고 scripts/fde_state.py preflight를 실행해 존재·파싱을 확인한다. 다운로드 버튼이 있다는 사실을 제출 폴더 저장 완료로 오인하지 않는다. URL만 요구하면 별도 JSON을 만들지 않는다. 이 키트는 플랫폼의 제출 버튼을 제어하거나 제출 성공을 보장하지 않는다.
요구된 결과가 저장되어 있고 실행·열람 경로가 확인되며, 중요한 미해결 항목을 숨기지 않았다. 단지 ‘테스트 통과’ 문장만으로 완료하지 않는다.


## 최종 설명의 근거 대조
초안의 핵심 주장마다 원본 대상 ID·연결 키·수치·단위·기준시점을 재조회한다. 구현됨과 미구현이라는 양방향 주장 모두 실제 코드와 최신 실행 증거를 대조한다. 예전 버전 설명을 최종 설명에 재사용하지 않는다. 코드가 있다는 사실만으로 동작 검증까지 완료했다고 쓰지 않는다.
필요한 주장만 내부 검토 기록으로 만들고 `scripts/review_guards.py --workspace . --claims worklog/claims.json`을 실행한다. 형식은 [claim-format.md](references/claim-format.md). 도구는 행 번호·인용·파일 변경을 확인한다. 인용이 문장을 의미상 뒷받침하는지는 직접 확인해야 한다. contradicted/partial/unverified 주장을 근거 없이 완료로 바꾸지 말고 설명을 수정하거나 제한을 표시한다. 내부 검토 JSON을 별도 제출하라는 뜻은 아니다.
