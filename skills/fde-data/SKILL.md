# 원문과 연결되는 데이터 만들기

응답과 새로 작성하는 사용자 화면 문구는 기본 한국어로 쓴다. 원문 인용·고유명사·코드 식별자는 보존한다. 뜻이 같은 한자나 일본어 단어를 한국어 설명에 섞지 않는다. 사용자가 다른 언어를 요청하면 그 요청을 따른다.

FDE_HARNESS.json이 있으면 실제 package·progress·state 경로를 확인한다. 없으면 현재 키트의 scripts와 과제 폴더의 기존 기록을 사용한다. 기록이 없을 때의 생성·미저장 처리는 fde-track을 따른다. 없는 WORKSTATE를 읽었다고 가정하거나 기존 기록을 초기화하지 않는다.
## 입력
파일 목록, 필요한 결과, 대상 식별자, 값·단위·기간·원문 위치. 키가 무엇인지 모르면 먼저 표의 열과 표본을 확인한다.

## 절차
1. 전체 파일·페이지·행의 범위를 센다. 읽은 수와 아직 읽지 못한 수를 따로 적는다. 도구 반환이 잘렸으면 다음 범위를 이어 읽는다.
2. 원본을 보존한다. ID 앞자리 0, 문자열/숫자 구분, 날짜·시간대, 단위, 빈칸·0·null·필드 없음의 차이를 유지한다.
3. CSV의 중복 헤더·깨진 행, JSON의 중복 키·비표준 숫자, ID 중복을 검사한다. 잘못된 행을 조용히 버리거나 마지막 값으로 덮어쓰지 않는다.
4. 여러 표를 합치기 전 결합키의 중복 여부와 일대일/일대다를 확인한다. 합친 뒤 원본 ID별 행 수, 누락, 예상하지 못한 증식을 확인한다. inner join으로 탈락시킨 행도 따로 남긴다.
5. 선택 정보 누락과 필수 정보 누락을 구분한다. 선택 메모가 비었다는 이유로 모든 자격을 미확인 처리하지 않는다. 필수 여부가 미정이면 업무담당자에게 확인한다.
6. PDF는 파일명·쪽수, 표는 레코드 번호와 실제 줄 범위, 이미지는 영역·축·범례·단위를 남긴다. OCR/텍스트 추출 실패를 ‘값 없음’으로 바꾸지 않는다. 시각적 원문을 직접 대조할 수 없으면 그 범위를 명시한다.
7. 위치 매핑은 원본 기호→원본 위치→대상 위치의 기호→출력 순서로 분리한다. 변환 방향, 중복 위치, 누락 기호를 먼저 확인한다. 한글 분해·키 매핑·재조합은 별도 단계다. 역변환 검사는 일대일 대응일 때만 가능하다.

## 코드 보조
PDF 읽기는 fde-pdf-read를 사용한다. 먼저 scripts/pdf_read.py --doctor로 실제 도구를 확인하고 쪽수·엔진·텍스트 희소/실패 상태를 보존한다. 읽은 범위와 남은 시각 검증은 progress에 연결한다.
키트 루트 scripts/data_audit.py는 CSV/JSON 구조와 ID 커버리지를 검사한다. scripts/mapping_check.py는 이미 확인된 토큰 간 일대일 변환만 검사한다. 둘 다 원문 판독·업무 정답을 대신하지 않는다.
실제 명령·입출력·실패 해석은 [데이터 도구 안내](references/data-tools.md)를 필요한 때 읽는다.

총 원본 / 처리 / 누락 / 중복 / 미확인 수와 실제 문제 ID를 같이 넘긴다. 모든 정상 행을 긴 설명으로 출력하지 않는다.
구조·연결이 확인되면 rules로, 읽기 실패가 남으면 해당 원문만 재확인한다.
