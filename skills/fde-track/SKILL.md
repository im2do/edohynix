# 대화가 바뀌어도 요청과 증거를 이어가기

응답과 새로 작성하는 사용자 화면 문구는 기본 한국어로 쓴다. 원문 인용·고유명사·코드 식별자는 보존한다. 뜻이 같은 한자나 일본어 단어를 한국어 설명에 섞지 않는다. 사용자가 다른 언어를 요청하면 그 요청을 따른다.

프로젝트 지침과 현재 과제를 우선한다. 이 스킬은 도메인 정책이나 사용자 대신의 승인 권한을 만들지 않는다.

## 매 작업 대화의 시작
읽기 전용 리뷰에서는 기존 기록만 조회한다. 없는 기록을 init으로 만들거나 요구·검증·완료 상태를 갱신하지 않는다. 아래 초기화·갱신 절차는 실제 기록을 만들거나 바꾸는 작업에 적용한다.
FDE_HARNESS.json이 있으면 progress·package 경로를 읽는다. 없으면 현재 키트의 scripts와 과제 폴더의 FDE_PROGRESS.json을 사용한다. 실제 스크립트 경로로 `fde_state.py status --workspace . --format markdown`을 실행한다. 상태 파일이 없고 쓰기가 허용될 때만 init으로 만들고 목표·출처부터 기록한다. init은 progress만 만들며 요약 파일·스킬·대화 백업은 만들지 않는다. 이미 있는 파일을 초기화하지 않는다. 쓰기나 실행이 금지되면 미저장·미실행을 표시하고 목표·누적 요구·미검증·다음 행동을 짧은 전달 메모로 남긴다. 저장한 척하거나 그 제한을 우회하지 않는다.

## 답변을 요구사항으로 옮기기
- 사용자의 최초 목표를 유지하고 새 기능을 별도 요구 ID로 추가한다. 새 요청이 왔다고 기존 배열 전체를 교체하지 않는다.
- 담당자에게 보낸 질문의 하위 쟁점을 나누어 각각 답변됐는지 확인한다. 답하지 않은 경계·권한·예외는 unresolved로 남긴다. 순서에 대한 답을 경계 허용의 답으로 간주하지 않는다.
- 한 요구에 확인 가능한 완료 조건 하나를 적는다. 원문 위치, 확정/제안/미정, 필수 여부, 관련 의존 요구를 기록한다. 사용자가 전달한 답변만 사용하고 비공개 정답 파일을 찾지 않는다.
- 규칙·범위·구현을 바꾸면 해당 요구를 갱신한다. 실패한 검증의 기대값을 구현에 맞춰 바꾸지 않는다. 새 규칙으로 바꿀 때는 근거를 남긴다.
- 기록 입력 형식과 예시는 [ledger-format.md](references/ledger-format.md)를 필요한 때 읽는다. 이 JSON은 사용자가 외우거나 직접 작성할 양식이 아니다. AI가 실제 대화와 작업에 맞게 작성한다.

## 구현과 검증의 분리
implemented는 실제 구현 파일을 연결했을 때만 사용한다. 검증 통과는 별도 checks에 원문에서 정한 기대값·실제값·로그 파일과 검사한 요구 버전을 기록한다. 코드가 존재하거나 AI가 완료라고 말한 것만으로 통과시키지 않는다.
요구 버전·연결된 구현·검증 로그 파일이 달라지면 예전 pass는 현 버전의 통과로 계산되지 않는다. 기존 검증 기록을 지우지 말고 새 검증 ID를 추가한다. 변경 때문에 영향받는 다른 요구도 함께 갱신한다.

업데이트는 patch 파일을 작성한 뒤 `scripts/fde_state.py update --workspace . --patch 변경분.json`으로 반영한다. expected_revision 불일치 시 현재 기록을 다시 읽고 자신의 변경분만 합친다. 이 도구는 한 작업자의 순차 갱신을 전제로 하며 병렬 쓰기 제어 서버가 아니다.

## 매 답변 마지막의 짧은 현황
업데이트 뒤 `scripts/fde_state.py status --workspace . --format footer`를 실행하고 출력된 다섯 줄을 답변 끝에 그대로 사용한다. 개수나 분류를 기억으로 다시 계산하거나 다른 말로 재분류하지 않는다. 다음 행동 한 줄만 직접 추가한다. ID는 AI가 관리하며 사용자가 부호를 외우게 하지 않는다. 전체 표는 파일에 둔다.

```text
목표: 합의한 사용자 작업
완료·검증됨: …개 — 기능명
구현됨·미검증: …개 — 기능명
미완료: …개 — 기능명
확인 필요: …개 — 미답변 조건/실패
다음: 지금 할 행동 하나
```

새 내용이 없는 설명 대화라면 상태를 불필요하게 다시 쓰지 말고 읽은 현황을 요약한다. 실제 기록·실행을 못 했으면 “미갱신/미실행”이라고 밝힌다. 스킬을 읽는 것만으로 자동 기억·자동 훅 실행이 생기는 것은 아니다.

## 정책 출처와 충돌 보존
새 업무 규칙을 기록할 때 policy에 업무 기준인지 설계 선택인지, 원문 출처와 짧은 인용을 남긴다. 담당자가 미정이라고 답한 내용을 AI나 사용자가 제안했다는 이유만으로 확정하지 않는다. 가정을 확정하려면 권한 있는 확인의 주체·위치·문장을 남긴다. 동일 문구가 후속 답변에 반복된 것만으로 승인됐다고 판단하지 않는다.
충돌하는 양쪽 출처를 conflicts에 보존한다. 열린 충돌이 있으면 구현이 존재해도 확인 필요다. 해결 뒤에는 resolution을 추가하고 의존 요구를 재검증한다. 기존 기록에 policy가 없으면 출처 미기록으로 드러내고 원문을 대조해 보충한다. 이 도구가 원문의 진위나 담당자의 권한을 자동 판별하는 것은 아니다.
형식은 [policy-format.md](references/policy-format.md)를 필요한 때만 읽는다.
