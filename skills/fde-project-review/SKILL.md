# 솔루션 기능별 점검

현재 프로젝트 지침과 도구·자료 접근 제한을 우선한다. 한국어로 설명하되 원문·고유명사·코드 식별자는 보존한다. 기본은 읽기 전용이다. 이 점검만으로 코드를 변경하거나 테스트를 실행하거나 기존 완료 기록을 갱신하지 않는다.

## 언제 사용하는가
기능을 구현한 뒤, 개발 중간의 현황 확인, 유지보수 시작, 결과 전달 전 점검에 사용한다. 완성되지 않은 기능도 포함한다. 새로운 기능을 제안하는 것이 아니라 현재 솔루션이 실제로 무엇을 읽고 처리하며 출력하는지, 어디까지 검증됐는지 보여준다.

## 확인 범위 정하기
1. 지정한 프로젝트의 README·현재 목표·실행 안내를 읽는다. 확인 시점, 대상 버전, 읽은 범위와 접근하지 못한 범위를 남긴다. Git이 없으면 현재 파일과 확인 시점으로 구분한다.
2. FDE_HARNESS.json이 있으면 progress·state의 실제 경로를 따른다. 없으면 존재하는 요구·결정·테스트 기록을 사용한다. 없는 기록을 추정하거나 새로 초기화하지 않는다.
3. 실제 진입점·화면·API·처리 함수와 누적 요구를 대조해 기능 목록을 만든다. 요청됐지만 미구현인 기능과 코드에만 존재하는 추가 기능도 구분한다. 관련 원문·파일·로그를 필요한 범위만 읽는다.
4. 데이터가 많으면 스키마·범위·식별키·대표 및 예외 사례·집계 기록을 확인하고 전체를 검사했는지 표본만 확인했는지 밝힌다. 추출 실패·출력 잘림을 값 없음으로 바꾸지 않는다. 다른 역할의 비공개 자료는 읽지 않는다.

## 각 기능에서 확인할 연결
- **실제 구현:** 사용자 행동 또는 처리 기능, 진입점·담당 함수·파일. 버튼이나 함수가 있다는 것과 내부 동작이 연결됐다는 것은 구분한다.
- **읽어오는 데이터:** 파일·테이블·API·폼의 실제 출처, 주요 필드·키, 기간·단위, 전체 대상과 현재 필터 범위, 결합 관계. 사용자 입력·원본 값·추정/가공 값은 섞지 않는다. 필드 이름만 나열하지 말고 어떤 판단에 쓰는지 연결한다.
- **중복 처리:** 무엇을 중복으로 보는지, 원본 보존·제외·병합·최신값 선택·거절 중 실제 동작이 무엇인지, 건수·판정·저장 결과에 어떤 영향을 주는지 확인한다. 고유 ID 중복, 합법적인 일대다 결합, 반복 요청을 같은 문제로 취급하지 않는다.
- **예외·경계:** 필수값 누락, 권한, 기준 충돌, 등호 경계, 재시도, 비해당 중 해당 기능에 존재하는 것을 확인한다. 발동 조건 → 처리 → 사용자 표시 또는 반환값을 연결한다. 구현되지 않은 예외를 처리했다고 쓰지 않는다.
- **근거·검증:** 업무 기준의 원문 위치, 실제 코드 위치, 검사한 입력·기대값·실제값·로그와 버전을 연결한다. 구현 이유는 기록된 결정에 근거하고 사용자 결정·담당자 요구·AI 제안·코드에서 관찰한 효과를 구분한다. 기록 없는 의도는 ‘의도 미기록’으로 표시한다.
- **출력·영향:** 화면·파일·API 응답·저장 상태와 그 결과가 집계·후속 후보·다음 행동에 미치는 영향을 확인한다. 화면 필터와 전체 처리 대상, 자동 판정과 사람의 결정이 실제로 구분돼 있는지 해당 기능에서 확인한다.
- **남은 확인:** 미구현·미검증·기준 미정·접근 불가를 분리하고 이유·영향·다음 확인 방법을 적는다. 확인하지 않은 것은 정상이나 완료로 분류하지 않는다.

## 검증 수준을 정확히 표시
코드에서 처리 발견 / 테스트 코드 존재 / 실행 기록 확인 / 화면 동작 확인을 구분한다. 테스트 코드만 있으면 ‘미실행’, 이전 코드 버전의 로그만 있으면 ‘현 버전 미검증’이다. 일부 테스트 통과를 해당 기능 전체 통과로 확대하지 않는다.

상태가 바뀌는 기능은 상태 → 파생 결과 재계산 → 다음 행동 → 저장·재열람 중 실제 확인된 범위를 연결한다. 읽기 전용 기능에 저장 단계를 강요하지 않는다. 비해당에는 이유를 붙인다.

이 리뷰에서 브라우저·마우스·키보드를 자동 조작하지 않는다. 화면은 기존 관측 기록을 확인하고, 확인이 필요하면 사용자가 직접 볼 동작과 기대 결과를 제시한다. 터미널의 별도 재검증이 필요하면 필요한 명령·예상 확인 범위를 제안하며, 요청되고 환경에서 허용된 경우에만 fde-verify 등의 검증 단계로 전환한다. 실행하지 않은 검사를 실행했다고 기록하지 않는다.

## 한눈에 보는 출력
[기능별 점검표 형식](references/review-format.md)을 사용한다. 서비스 흐름을 짧게 보여준 뒤 기능별 입력 → 처리·예외 → 검증 → 출력·영향 → 남은 확인을 한 표에 연결한다. 내부 기록의 ID는 유지하되 사용자가 코드를 외우게 하지 않는다.

필수·미완료 기능이 요약에서 빠지지 않게 한다. 기능이 많으면 주요 흐름별로 묶고 상세 목록 위치와 요약한 범위를 밝힌다. 매번 전체 대화·파일을 출력하지 않는다. 중요한 주장에는 파일·함수·행/쪽수·기록 위치를 붙인다.

마지막에 완료 여부를 바꾸거나 사용자 결과에 영향을 주는 미검증 사항부터 정리한다. 결과 문서 생성은 구현 완료나 제출 완료가 아니다.

## 기존 스킬과 연결
- fde-track: 누적 요구와 상태를 읽어 기능 누락을 확인한다. 기록과 실제 코드가 다르면 차이를 보고하고 임의로 상태를 고치지 않는다.
- fde-data / fde-pdf-read: 관련 자료의 추출·연결을 확인할 필요가 있을 때만 사용한다. 보조 스킬을 읽어도 이 리뷰의 읽기 전용 범위는 유지한다. 원문이나 기존 기록을 변경하지 않으며 별도 실행 검증은 자동 시작하지 않는다.
- fde-verify: 별도 실행 검증이 요청된 경우 연결한다. 계획과 실행 결과를 구분한다.
- fde-deliver: 결과 전달이 요청되면 실제 실행 경로·산출물·제한을 넘긴다. 현재 요구에 없는 제출 파일을 추가하지 않는다.

## 완료 기준
기능 목록과 실제 코드·누적 요구를 대조했고, 각 기능의 입력·처리·예외·출력·영향·검증 수준이 연결되며, 누락·미정·미검증 범위를 드러냈으면 점검을 마친다. 설명을 맞추려고 기준이나 실패 기록을 바꾸지 않는다.
